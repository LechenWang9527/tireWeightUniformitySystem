# 05. 工序路径拆分与机台贡献度计算 (Process Path Splitting & Machine Contribution)

---

## 1. 为什么必须进行机台工序路径拆分？（业务背景与必要性）

轮胎制造属于典型的**物理流式传导过程**，一条成品轮胎先后流经 **成型 (GT) ➔ 硫化 (CT) ➔ 终检 (TU)** 多道工序。

在此流式加工过程中，**机台之间存在不可忽视的相互影响与交叉干扰**：
* 某台成型机加工精度很高，但若下游流向了模具老化的劣质硫化机，终检成品依然是不良品；
* 反之，成型段微小的加工偏差，也可能被下游状态极佳的硫化机掩盖。

如果仅按单台设备粗放统计终检结果，必然会引发因果归因误判。

### 1.1 核心解决方案：控制变量路径拆分
系统在算法服务 **`backend/services/process_flow_service.py`** 中构建了**全工序路径拆分机制**：
* 将整厂流水线切分为“成型机 ➔ 硫化机 ➔ 终检机”的离散固定通道（如 `TB254 ➔ CU621 ➔ TU05`）；
* **控制变量法**：评估某工段机台的真实质量时，**严格锁定其上下游关联设备**，彻底隔离其他工序的随机扰动，还原设备自身加工质量。

---

## 2. 机台边际贡献度的具体计算方式

在固定受控路径的前提下，系统计算设备质量表现与基准线的偏差值：

$$Contrib = CPK_{mach} - CPK_{\text{受控基准}}$$

* $Contrib < 0$：该机台在当前路径中处于**负贡献（拉低质量）**；
* $Contrib > 0$：该机台在当前路径中处于**正贡献（提升质量）**。

---

## 3. 为什么需要数据平滑？产量平方根平滑算法 (Square-Root Smoothing)

单纯看 $Contrib$ 无法反映产量规模的影响，但如果直接按产量线性加权，又会导致工业界经典的“大机台替人背锅”现象。

### 3.1 引入数据平滑的必要性
* **避免满载大机台背锅**：承担全厂绝大部分排产的主力机台，即便发生万分之几的正常微小波动，一旦线性乘以极大产量，负向扣分也会被过度放大，被误判为第一故障元凶；
* **避免故障小机台漏警**：排产量极小但设备严重劣化的机台，若仅按极小产量线性打折，扣分微乎其微，容易被系统直接忽略；
* **核心价值**：引入**数据平滑**算法，**既兼顾了机台的生产数量规模，又兼顾了机台的真实质量贡献度**。

### 3.2 产量平方根平滑公式
系统将线性产量权重优化为**产量平方根占比**（核心服务位于 **`backend/services/machine_service.py`**）：

$$ImpactScore = Contrib \times \frac{\sqrt{N_{mach}}}{\sum_{i} \sqrt{N_i}}$$

通过 $\sqrt{N}$ 非线性压缩函数，科学缩小了极值产能差距，既保留了大样本机台的置信度，又让异常小机台能及时触发警报。

## 4. 核心规格拉低评分 (Stable Score / 拖累分)

### 4.1 这是什么？
在系统后端核心代码（**`backend/services/article_service.py`**）中定义为 `stable_score`，在看板前端界面上直观展现为**【拖累分】**。

$$StableScore = (CPK_{\text{全厂加权综合}} - CPK_{\text{单规格}}) \times N_{\text{规格}}$$

* **质量恶化深度**：$CPK_{\text{全厂加权综合}} - CPK_{\text{单规格}}$，度量该规格偏离全厂合格水准的严重程度；
* **影响波及广度**：乘以排产条数 $N_{\text{规格}}$，度量该规格对全厂质量大盘的产量波及范围；
* **业务含义**：单个规格 CPK 越低、当天排产量越大，其“拖累分”负向绝对值越大。

### 4.2 这个和前端哪个模块有关？
该指标直接驱动前端看板 **Row 3（第三行左侧）的【核心规格行动表】（Spec Action Table）**：
* 当用户点击顶部 CPK 趋势图中的某一天时，系统通过 `stable_score` 自动对当天全厂在产规格排序；
* 拖累全厂最狠的重点规格会自动置顶并标注红/橙预警，指引现场工程师第一时间攻坚排查最核心的问题规格。
