# 研究型阅读路线（只为"读懂"，不为"接手"）

> 适用场景：你不需要改代码、不需要部署、不需要背 API，只想在**几个小时内**真正搞明白——
> 这套系统在替车间做什么判断？判断的依据是什么？它的边界在哪？
>
> 与《如何读懂这个项目-方法论.md》的区别：那份是"能改代码"的工程路线（要 build、要跑测试、要做三个改动验证）；
> 这份是**研究路线**——不跑环境、不读 UI、不碰 CRUD，只读"决策"。

---

## 一、先定三条原则

| 原则 | 含义 | 具体动作 |
|---|---|---|
| **只读决策，不读实现** | 实现是"怎么做"，决策是"为什么这么做、凭什么这么判" | 跳过全部 `.vue`、跳过 routers 里的参数校验、跳过样式 |
| **文档先行，代码验算** | 文档给你框架，代码只用来核对关键数字 | 先读 wiki 的 10 篇，再用 4 个短文件核对 |
| **每读一段，必须能讲成人话** | 讲不出来 = 没读懂 | 每个单元产出一段 150 字的"外行版解释" |

> 一句话：**这是一个"规则系统"，不是一个"网站"。研究它 = 研究它的规则。**

---

## 二、六个阅读单元（每单元 40~60 分钟）

### U1 · 它在替谁做决定（40 min）

**读**：`wiki\README.md`（29 行）→ `wiki\01_system_architecture.md`（125 行）→ `wiki\06_frontend_dashboard_views.md`

**抓**：四个业务痛点（指标统一 / 全流程溯源 / 瓶颈定位 / 闭环干预）+ 五块主屏幕。

**产出（150 字）**：
> 每天早上质量工程师打开它，先看 ___，发现异常后点开 ___，最后得出 ___ 的结论。

**跳过**：`wiki\06` 里的组件名、Props、状态管理那部分——那是给前端看的。

---

### U2 · 数据凭什么可信（50 min）

**读**：`wiki\02_data_sources_and_er.md` → `wiki\03_etl_pipeline_and_engine.md`

**抓三条"口径约定"**（这是全系统的地基，比任何算法都重要）：

1. **量纲**：TU 峰谐波 ×10 才是牛（N）；TG 统一毫米；TB 是克；
2. **班次**：工业日 = 08:00 → 次日 08:00，**不是自然日**（历史上因此出过左右两图数字对不上的 bug）；
3. **分期**：机台分三期/四期，**绝不跨期比较**。

再加一条数据来源的关键：限值只来自 `Recipes.csv`，**没配就不参与计算**，不许设默认值。

**产出**：一张 A4 血缘图（Redshift → parquet → DuckDB → 接口），标出每一步"改了什么口径"。

**跳过**：`fetch_data.py` / `clean_data.py` 的全部代码。文档里的规则描述已经够；想核对时再看 `clean_data.py`（353 行）里的 SQL 片段。

---

### U3 · 17 个指标与 CPK 的真身（50 min）

**读**：`wiki\04_metrics_and_standard_cpk.md` → `backend\core\cpk.py`（**118 行，全读，这是唯一值得精读的代码文件**）

**为什么只读这一个文件**：它里面的 `INDICATORS_SPEC` 字典是全项目的**索引表**，18 条记录把"业务指标 → 数据库列 → 限值来源 → 量纲倍率 → 单/双侧公差"全部串起来了。看完这张表，17 个指标就不用再背。

**抓**：
- 单侧 `CPK=(USL-μ)/3σ`；双侧 `CPK=min((USL-μ)/3σ,(μ-LSL)/3σ)`；
- 结果截断到 `[-5, 5]`（为什么？因为负 CPK 有业务含义——均值已经超出上限）；
- `σ ≤ 1e-6` 返回 `1.33`（为什么？产线极其稳定的数学退化，给一个"合格"的约定值）。

**产出**：一张三列小表——指标 / 单位 / 单侧还是双侧。

---

### U4 · 最值钱的那个算法（60 min）

**读**：`wiki\05_core_algorithms_deepdive.md` → `MEMORY_SUMMARY.md` 的 **"2026-08-27 产量平方根平滑"** 那一节

**抓这个案例**（全项目最漂亮的一段业务推理）：

> 旧算法按产量线性加权 → 产量 1300 胎的 `TU8` 占了 98% 权重，"替人背锅"排第一；
> 真元凶 `CU621` 只有 50 胎，CPK 崩到 0.31，却因权重仅 9.6% 被压到几乎看不见。
> 改成 `影响分 = 净负偏离 × √产量 / Σ√产量` 后，26 倍的产量差距被压缩到 **5.1 倍**，`CU621` 立刻登顶。

**这一节读透了，你就理解了整个系统的价值观**：它要的不是"最大的机台"，是"最该被修的机台"。

**产出**：用一句话解释"为什么用 √ 而不是直接除"（提示：既要考虑产量影响，又不能被产量绑架）。

**代码核对（可选，15 分钟）**：`services\machine_service.py` 里搜 `sqrt`，只在函数体内看那 5 行。

---

### U5 · 它怎么证明"是这次调参导致的"（60 min）

**读**：`wiki\06_cgrs_parameter_tuning_and_recommendation.md` → `MEMORY_SUMMARY.md` 里 CGRS 相关章节

**抓五个约束**（这是因果推断的护栏，全部有业务理由）：

| 约束 | 数值 | 为什么 |
|---|---|---|
| 改前改后样本量 | 各 ≥ 5 胎 | 少于 5 胎算不出有意义的方差 |
| 单侧最多取 | 20 胎 | 调参后工艺会继续漂移，取太多会混入后续变化 |
| 跨天限制 | 最多 1 天 | 防止把两天的批次混为一谈 |
| 样本失衡比 | > 2.5 倍整条剔除 | 改前 20 胎 vs 改后 2 胎，比较没有意义 |
| 路径拆分 | 按 GT→CT→TU 拆 | 只有"其他工序不变"的路径，差异才能归因到这一次调参 |

**产出**：能回答"为什么不能简单比较调参前后的平均值"。

---

### U6 · 这套系统的边界在哪（40 min）

**读**：`wiki\07_devops_and_troubleshooting.md` 的 §4 四条红线 + `MEMORY_SUMMARY.md` 里反复出现的问题

**四条红线**（研究视角看，它们其实是"系统的四个已知失效模式"）：

1. 不许伪造公差 → 失效模式：**没配限值的规格被静默排除**（数字好看但样本变少）；
2. 不许跨工段/跨期推荐 → 失效模式：**物理上不可比的机台被强行比较**；
3. 不许时间穿越 → 失效模式：**用未来数据解释了历史异常**（最隐蔽，也最致命）；
4. 不许核心层反向依赖 → 失效模式：循环导入，系统起不来。

**产出**：一份"我能信它到什么程度"的清单——哪些结论可以直接拿去开会，哪些必须回原始数据复核。

## 三、如果你只有两小时

按这个顺序，其余全跳过：

```
① wiki\01（125 行，20 min）      → 知道它解决什么
② wiki\04 + core\cpk.py（40 min） → 知道数字怎么算
③ MEMORY_SUMMARY 的 08-27 平方根平滑（25 min） → 知道它最聪明的地方
④ wiki\07 的四条红线（15 min）    → 知道它会在哪骗你
⑤ 自己讲一遍（20 min）            → 讲不顺的地方就是没懂的地方
```

两小时换来的不是"会改"，而是**能在会上听懂、能判断别人说的对不对**。

## 四、研究型读者的四个提问法（代替"改代码验证"）

不用动手，也能验证自己是否读懂：

| 提问法 | 例子 | 检验什么 |
|---|---|---|
| **反事实** | 如果把 √ 换回线性加权，`TU8` 会排第几？`CU621` 会掉到哪？ | 你是否真懂公式的作用 |
| **边界** | 某规格在 `Recipes.csv` 里没配 RFH1 的 USL，系统会算出什么？ | 你是否真懂"不许造假兜底" |
| **一致性** | 为什么左侧行动表的 N 必须等于右侧桑基图的总流向？不相等说明什么？ | 你是否真懂班次口径 |
| **溯源** | 图上某天 CPK 突然掉到 -2，你会按什么顺序排查？ | 你是否真懂数据链 |

## 五、建议的产出物：一页《系统心智模型》

读完不要写读书笔记，写**一页纸**，四栏：

```
┌─ 输入 ─────────┬─ 规则 ──────────┬─ 输出 ─────────┬─ 边界 ────────┐
│ Redshift 宽表   │ 量纲/班次/分期   │ ① 全厂 CPK 趋势 │ 没配限值不算   │
│ MES CGRS 调参   │ CPK 公式与截断   │ ② 规格行动表    │ 不跨期比较     │
│ Recipes 配方限  │ √产量 归因      │ ③ 工序桑基图    │ 样本 <5 不判   │
│                 │ 5胎/20胎/2.5倍   │ ④ 批次追溯      │ 只回溯 30 天   │
│                 │ 30 天回溯窗      │ ⑤ 调参建议      │               │
└─────────────────┴─────────────────┴────────────────┴───────────────┘
```

这张纸能讲清，研究就结束了。
