## 一、这个目录里到底是什么

`D:\Ava` **不是一个单一仓库**，而是一个"项目 + 原型 + 杂项"混放的开发工作区。真正在跑的项目是：

> **轮胎质量与均匀性分析及 Cpk 诊断系统**（Tire Weight & Uniformity Analysis & Cpk Diagnostics System）

业务目标：对均匀性不良指标（TU / TG / TB 共 17 项）做异常监控与根因定位，具体解决四件事：

1. **指标统一监控**——全厂 17 项检测指标的公差、量纲、加权 CPK 与 SPC 控制限统一呈现；
2. **全流程穿透溯源**——原材料 → 半部件批次(Lot) → 成型(GT) → 硫化(CT) → 终检(TU) 的时序血缘；
3. **精准瓶颈定位**——用"产量平方根平滑"消除大产量机台背锅，揪出真正的劣化设备；
4. **闭环工艺干预**——结合 MES 的 CGRS 调参日志，回溯调参效果并给出参数建议。

## 四、主线技术栈与架构

| 层 | 技术 | 职责 |
|---|---|---|
| 前端 | Vue 3.5 + Vite + Element Plus + ECharts + Pinia | 大屏看板、桑基图、树图、趋势图 |
| 后端 | Python FastAPI + Uvicorn（:8088） | 异步 API 与路由装配 |
| 计算 | DuckDB（常驻内存，`max_memory=4GB`）+ Pandas/NumPy | 亿级列存 Parquet 流式聚合 |
| 上游 | Redshift（psycopg2）、MES CGRS（SQL Server/pyodbc） | 增量 ETL 拉数 |

**六层单向依赖**（`wiki/01` 的架构红线，改代码必须遵守）：

```
物理数据层 → ETL 管道 → 计算核心层(core 纯函数) → 业务服务层(services) → API 路由层(routers) → 前端呈现层
```

- `backend/core/` **严禁** 反向 import `backend/services/`；
- 服务之间跨调用用**延迟解析钩子**，不许文件顶部互相 import（避免循环依赖）；
- `backend/main.py` 只做装配，不写业务 SQL。

```

   │  backend/etl/fetch_data.py      （安全水位线增量抽取）

   │  backend/core/db.py             （载入 DuckDB 内存表 clean_yield）
```

```powershell

```

> 需要能连 Redshift；凭据在 `backend\config\db_config.json`（XOR+Base64 密文）+ `secret.key`。

## 八、改动前必读的四条红线

1. **不许伪造公差**：`Recipes.csv` 里没配 USL/LSL 的规格，直接不计入 CPK，不许设默认值兜底；
2. **不许跨工段/跨分期推荐**：成型(TB/GT)只和成型比，硫化(CU/CT)只和硫化比；三期不许混四期；
3. **不许时间穿越**：查任意历史日，检索范围强制锁 `[target_date-30天, target_date]`；
4. **不许核心层反向依赖**：`backend/core/` 不能 import `backend/services/`。

另外两个已经踩过的坑：

- **CPK 口径必须统一**为 `calc_cpk()`（截断 `[-5, 5]`，`std<=1e-6` 返回 `1.33`），全局搜 `max(0.0` 应为 0 处；
- **班次口径**：工业生产日是 08:00→次日 08:00（`tu_first_loc_timestamp - INTERVAL 8 HOUR`），左右两侧图表必须一致。
